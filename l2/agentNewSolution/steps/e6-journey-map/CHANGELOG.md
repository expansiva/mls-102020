- 2026-07-31 — **required-id source decided at e6 (ajustesTemplates §2)**. The e7 lint could only REPORT `template.input.idWithoutSource` (a cross-workspace picker injected there breaks the detail/map equality and coverage gates), but the real fix belongs to whoever DESIGNS the workspace — while it is still cheap. New gate rule `validateCommandIdSources` (4 tests): a command input that is `required` and looks like an id (`id` / `<entity>Id`) must declare a source, and it must RESOLVE INSIDE the workspace — `selection` + sourceRef = a query bffId of this workspace, `derived` + sourceRef starting at a local bffCall, or `pageInput`/`actorSession` (no ref). Missing source or `userDecision` on an id is now an ERROR (`bff.input.idSourceMissing`), which the detail retry can always satisfy: either add the picker query over an operation the workspace ALREADY hosts, or declare that the id arrives with the page — and the error message names both ways out, so the retry is never blind. `promptDetail.md` gained the same two outs, explicitly numbered. The id-name convention is now a single exported helper (`isNsIdInputName`) shared with the e7 lint, so the two cannot drift.

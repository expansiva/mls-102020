# agentDefsL2

Deterministic entry and declared flow for producing L2 definition sources from an approved L4 plan.

Invocation: `@@agentDefsL2 <lowerCamel>` or `/help`. An existing task may add an `agent` step with
JSON args `{ "project": 102047, "module": "agendaClinica" }`. Both forms plant the same six-step
plan; only the message entry creates an `add-message-ai` intent.

Current delivery implements `entry10`, deterministic `input20`, deterministic `contracts30`,
per-page LLM `shared40` and per-page LLM `pages50`, each LLM unit with one bounded repair.
The input phase freezes coherent L4/planner inputs with content hashes, exact page destinations and
structured review findings. The contracts phase gates and reconciles one typed contract per selected
create/update page and publishes a hash-verified barrier. Shared and page11 emit a single serializable
`definition` export with semantic references. Contracts retain their typed DTOs and route constants.
The product contains no pipeline, execution plan or materialized `.ts` dependency.
Pages research molecules in two phases: assess catalog groups by organism/device need, then read
only relevant indices and usage contracts to choose a preferred option and optional alternative.
Full research, coverage, selected template hashes and reference hashes live in D2 receipts.
`finalize60` resolves the document graph, revalidates consumed sources and requires real Studio
TypeScript results for every current artifact. An unavailable compiler blocks completion.
Changed shared content invalidates both devices of its page; unrelated pages remain reusable.
Format revisions invalidate old receipts. The former M2 pipeline reader is intentionally incompatible
with these products and is not executed or adapted by D2.
No publication, room message or L5 mutation exists here.

State belongs only to `l2/<module>/pipeline/agentDefsL2/`.

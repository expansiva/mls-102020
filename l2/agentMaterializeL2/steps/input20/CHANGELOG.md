# input20 — CHANGELOG

- 2026-10-05: created for agentMaterializeL2 (phase A), from the generic gate of agentMaterializeL2v2 (refactor of 05/10).
  - The contract reader is a copy of the official parser (`helpers/defs/contract.ts`). It exposes the route JSDoc and the projection leaves, and accepts the empty hub contract `export {};`.
  - New: the L4 context (`helpers/l4/context.ts`), sliced per page and stored in `input.json`. Its hash is part of every unit.
  - Notes `M4_INPUT_L4_LANGUAGES` and `M4_INPUT_L4_ONTOLOGY` when the L4 is incomplete.
- 2026-10-07: the shared states may list `organisms`. agentDefsL2 requires that field since d2_80 (05/10). The reader in `helpers/defs/shared.ts` accepts it as optional and keeps its value. agendaClinica was refused with `forbidden field organisms`.
- 2026-10-07: **context inputs** (`contextInputs` in `input.json`, note `M4_INPUT_CONTEXT_INPUT`).
  - A top-level member of a form's command input is context when an entry param with a `select:` effect has the same name and a state takes its `source` from that param. It is the page's selection, not something the form asks for.
  - Case: comandaRestaurante/atendimento, `lancarItem.comandaId ← selectedComanda`. The draft held `comandaId`, nobody filled it, and the command was refused in the browser before reaching the BFF.
  - The match uses only the links the defs declare (contract input ↔ entry param ↔ state source), with no module names.
  - The note enters the shared40 rules, so it also changes the `rulesHash`, and the shareds it affects are regenerated.
- 2026-10-13: **the frozen shared structure** (Wagner, d2_94: no `forms`, no `functions`, `rules` is one list, params carry `required`).
  - The shared is read by the official format, `_102020_/l2/helpers/sharedV2/format.ts`, imported instead of copied (`helpers/defs/shared.ts`). A shared in the old structure is refused with `M4_INPUT_DEFS_FORMAT` (`forbidden field forms/functions`): comandaRestaurante and agendaClinica must be regenerated by agentDefsL2.
  - `methods`: a page11 intent resolves to the request of its id or of its trigger. Every request is a shared method of its own id.
  - New `navigations` in `input.json`: a navigate intent becomes a shared method of the intent id, with the target page and its entry params (there is no navigation function any more).
  - `contextInputs` now come from the page11 submit intents (there are no forms). The field `form` became `organism`.
  - New note `M4_INPUT_RETURN_UNREAD`: a command returns a member no state reads (reembolsoDespesas: `item`, the list row next to the record). Its route comment says where it goes.
  - Removed: `M4_INPUT_FUNCTION_REF`, `M4_INPUT_STATE_UNKNOWN`, `M4_INPUT_CARRIES_TARGET`, `M4_INPUT_NAVIGATE_UNSERVED`.
  - `helpers/l4/context.ts` reads `rules` as a list; with the old shape the page rules never reached the L4 slice.
  - Schema `2026-10-13-materialize-l2-input-v3`. Fixtures: `reembolsoDespesas.json` (the first real module in the frozen structure, 13/10), and `controleEstoque.json` with its shared converted to the frozen structure.
- 2026-10-14: `M4_INPUT_L4_LANGUAGES` also notes two product languages that are one catalogue key (`pt-BR` and `pt_br`, `helpers/locale.ts`); the pages declare it once.
- 2026-10-14: **UX variants** (`web/<device>/page21/…`, the "genomes" the shell cycles with Ctrl+Alt+E).
  - `discoverM4Variants` looks for page12…page99 folders with defs of the page; `checkVariant` parses both devices at their own folder and requires every intent to be one the primary page11 already resolves (the variant reuses the page's shared). A variant that fails is left out with the warning `M4_INPUT_VARIANT_REFUSED`; the page is never refused for it.
  - `input.json` (schema `2026-10-14-materialize-l2-input-v4`): `variants: [{ genome, status, inputs, units }]` per page, units `<pageId>__<device>__<genome>`.
  - A page11 file whose fileReference names another folder is refused as `M4_INPUT_DEFS_LOCATION`.
- 2026-10-14: the **shared unit fingerprint leaves out the product languages** of the L4 slice: the shared writes no visible text, so adding en-US and es-ES to reembolsoDespesas regenerated every shared for nothing. The page units still include them (the pages write the catalogues). Every shared fingerprint changes once with this rule.
- 2026-10-16: note **`M4_INPUT_REQUIRED_PARAM`** (`m4RequiredParams`) for every `required: true` entry param: the request inputs it feeds, whether that is the opening load, and what the route comment says about the input. tarefas: `termo` feeds only a search, `avisoId` only the opening of a notice, `responsavelId` "vem do contexto, nunca da tela" (TASK-102020-materialize-l2-required-entry-params).
- 2026-10-22: **variant molecules** (TASK-102020-genome-ux-3, scope 5). `checkVariant` also checks, per device, the `molecules` of a variant (page12…page99): every tag (preferred and alternative) must be in the catalog (`M4_INPUT_VARIANT_MOLECULE_UNKNOWN`) and in no group of the template's `groups.forbid` (`## Molecule rules`, phase 2; group = the tag prefix before `--`, ignoring case: `M4_INPUT_VARIANT_MOLECULE_FORBIDDEN`). Rules that cannot be read: `M4_INPUT_VARIANT_TEMPLATE_RULES`; a legacy template without the section restricts nothing. Each one is a warning and leaves the variant out (`M4_INPUT_VARIANT_REFUSED` lists the reasons); the page is never refused for it, and page11 keeps the note `M4_INPUT_MOLECULE_UNKNOWN`.
  - The gate gets the template text (`templateText`, from the templates run.ts already reads). The extractor is a private copy (`helpers/templateRules.ts`) of `aura/helpers/templateRules.ts`; a test keeps them identical on every collabux template.
  - Cache: the variant unit hash already had the full template text, so a change of rules changes the units; a variant the new rules refuse loses them. Schema unchanged.

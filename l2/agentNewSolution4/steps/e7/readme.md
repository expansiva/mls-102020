# E7 — realization

E7 is an automated compiler after the sixth and final clarification. It groups identical journey step
ids into stable N→1 use cases, details each use case with a `parallel_dynamic` reasoning worker, runs a
deterministic targeted repair for invalid drafts, derives lifecycle workflows and emits permanent typed
L4 contracts.

Each use case keeps only its description, E2 context ids, canonical inputs/outputs, E4 reads/writes,
behavior-owned E5 rule ids, expected business errors and real lifecycle transitions. Actors, authorities,
data scopes, endpoint access patterns, ports and transaction policies stay with their actual owners.
Old oversized drafts are rejected by version; a resume reuses only drafts from this simple contract.

The step never edits journey `business` and verifies its `businessHash`. It writes only realization
metadata back to journey/access contracts. E3 realization derives authority links from journey-step refs;
E8 operations are the future channel integration endpoints, and backend generators choose their architecture.

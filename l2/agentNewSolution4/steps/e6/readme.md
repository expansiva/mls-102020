# E6 — additional composition

E6 is the sixth and final human clarification. It analyzes whether the approved module requires a
horizontal business module or an external plugin before realization.

The step is intentionally conservative: an empty recommendation list is valid, platform baseline
capabilities are excluded, and approval writes one permanent `composition/additional-capabilities.defs.ts`.

Runtime plan ids keep the historical `e6-behaviors` name only as a stable internal identifier. The
permanent artifact and the widget use the clearer composition terminology; prior flow versions are
rejected rather than migrated.
